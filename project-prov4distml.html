SUMMARY / RESUMO

Overview

Distributed Machine Learning (or simply Distributed Learning) and its branches, such as Federated Learning, represent approaches that enable collaboration among multiple devices or users in training Machine Learning models, including deep neural networks and clustering algorithms. These techniques have been widely applied in areas such as Astronomy, Medicine, and Biology due to their ability to accelerate the training of complex models by distributing the processing across multiple machines. In particular, Federated Learning allows training to occur without the need to centralize data, thereby preserving privacy and security, making it ideal for scenarios involving sensitive data, such as personal information.

In a typical configuration, each worker (e.g., smartphones, computers, or clusters) trains a model locally and sends model updates to a central server. This server combines the contributions into a global model, which is redistributed for new training rounds. Distributed training is an iterative process that can be time-intensive, with its duration influenced by factors such as aggregation methods, hyperparameter choices, and the characteristics of the datasets used. The analysis of metrics such as accuracy and fine-tuning of configurations during distributed training enables important improvements, such as increased efficiency, better model interpretability, and higher fault tolerance.

In this context, provenance data emerges as a promising solution to represent and track the lifecycle of artifacts generated during the distributed learning process, such as datasets, applied transformations, trained models, and adopted configurations. These data not only enable the monitoring and analysis of training but also allow interventions, such as dynamic parameter adjustments and configuration adaptations.

The PROV4DistML project aims to develop solutions to capture, model, store, and manage provenance data in Distributed and Federated Learning applications. Additionally, the project seeks to leverage these data to support actions such as automatic parameter tuning, improving result interpretability, and increasing the robustness of training. In this way, PROV4DistML contributes to the development of more efficient, transparent, and resilient solutions in Distributed Learning.

Resumo em português

O Aprendizado de Máquina Distribuído (ou simplesmente Aprendizado Distribuído) e suas vertentes, como o Aprendizado Federado, são abordagens que permitem a colaboração entre múltiplos dispositivos ou usuários no treinamento de modelos de Aprendizado de Máquina, incluindo redes neurais profundas e algoritmos de agrupamento. Essas técnicas vêm sendo amplamente aplicadas em áreas como Astronomia, Medicina e Biologia, por acelerarem o treinamento de modelos complexos ao distribuir o processamento entre várias máquinas. Em particular, o Aprendizado Federado permite que o treinamento ocorra sem a necessidade de centralizar os dados, preservando a privacidade e a segurança, o que o torna ideal para cenários com dados sensíveis, como informações pessoais.

Em uma configuração típica, cada worker (e.g., celulares, computadores ou clusters) treina um modelo localmente e envia as atualizações desse modelo a um servidor central. O servidor combina as contribuições em um modelo global, que é redistribuído para novas rodadas de treinamento. O treinamento distribuído é um processo iterativo e potencialmente demorado, cuja duração é influenciada por fatores como o método de agregação, a escolha de hiperparâmetros e as características dos conjuntos de dados utilizados. A análise de métricas como a acurácia e o ajuste fino das configurações durante o treinamento distribuído permitem melhorias importantes, como maior eficiência, melhor interpretabilidade dos modelos e maior tolerância a falhas.

Nesse contexto, os dados de proveniência surgem como uma solução promissora para representar e rastrear o ciclo de vida dos artefatos gerados durante o aprendizado distribuído, como conjuntos de dados, transformações aplicadas, modelos treinados e configurações adotadas. Esses dados não apenas permitem o monitoramento e a análise do treinamento, mas também intervenções, como ajustes dinâmicos de parâmetros e adaptações de configuração.

O projeto PROV4DistML tem como objetivo desenvolver soluções para capturar, modelar, armazenar e gerenciar dados de proveniência em aplicações de Aprendizado Distribuído e Federado. Além disso, o projeto busca utilizar esses dados para apoiar ações como a sintonia automática de parâmetros, a melhoria da interpretabilidade dos resultados e o aumento da robustez do treinamento. Dessa forma, o PROV4DistML contribui para o desenvolvimento de soluções mais eficientes, transparentes e resilientes em Aprendizado Distribuído.

GOALS

Objectives

  1. Capture provenance across the training lifecycle

    Record the artifacts that distributed and federated training produces and consumes: datasets, applied transformations, trained models, and adopted configurations.

  2. Model and store provenance data

    Define how these data are represented and stored so that the derivation path of each model stays queryable while training is still running.

  3. Monitor and analyze distributed training

    Relate metrics such as accuracy, round by round, to the aggregation method, the hyperparameters, and the characteristics of the datasets used.

  4. Steer training at runtime

    Support interventions guided by provenance, such as automatic parameter tuning, dynamic parameter adjustments, and configuration adaptations.

  5. Make results easier to interpret

    Let users explain how a model was obtained by tracing it back to the data, transformations, and configurations that generated it.

  6. Increase the robustness of training

    Use the recorded history to make long, iterative distributed training more efficient and more tolerant to failures.

HOW IT WORKS

Provenance in a distributed training round

  1. STEP 01Datasets & transformationsLocal datasets and the transformations applied to them on each worker.
  2. STEP 02Local trainingWorkers (smartphones, computers, or clusters) train a model locally and send updates.
  3. STEP 03AggregationThe server combines the contributions into a global model using an aggregation method.
  4. STEP 04Global model & configurationsThe model, its metrics, and the configuration of the round are redistributed for the next round.

Repeated for every training round

PROVENANCE LAYERCapture→Model & store→Monitor & analyze→Intervene

Actions supported by provenance

Once captured, the same provenance database serves three goals of the project.

Automatic parameter tuning

Adjust hyperparameters and configurations between rounds, based on how previous rounds behaved.

Interpretability

Explain a trained model by its derivation path: which data, transformations, and configurations produced it.

Robustness

Rely on the recorded history to make iterative, time-intensive training more efficient and more fault tolerant.

FLARE-PROV

Federated k-means clustering with scikit-learn, using MiniBatch-style aggregation, instrumented with DfAnalyzer to capture prospective and retrospective provenance of each round.

JavaScript · Federated learning

FedObserve

Web application for managing and visualizing federated learning experiments, with a t-SNE service for model inspection. Uses AkôFlow for AWS provisioning and execution monitoring.

Code
Python · Deep learning

DLProv

Provenance services for deep learning workflows, covering pre-processing, training, and evaluation. Supports online analysis in MonetDB, W3C PROV documents, and Neo4j graphs.
